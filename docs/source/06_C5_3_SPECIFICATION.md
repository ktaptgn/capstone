## Version and Status
- **Version**: C5.3
- **Effective Date**: 2026-06-13
- **Status**: Implemented; results in `06_C5_3_RESULTS.md` (generated by the sweep).
- **Builds on**: C5.2 (`05_C5_2_SPECIFICATION.md`). Self-contained new `c5_3` module; the C5.1/C5.2 code is unchanged.

## 1. Purpose

C5.3 transplants the RL-Lab **C6 reliability model** into the **C5 capstone mine**, then asks a single, fair question: with preventive maintenance fixed to one shared rule, **how much does the dispatch policy alone change total cost of ownership** when health is 3-dimensional, heterogeneous across trucks (frailty), and observed only through noisy sensors?

It is the C5.2 heuristic comparison re-run on a richer, harder reliability surface, with the decision narrowed to dispatch (the C6.1 protocol).

### Definition (as commissioned)
| Element | C5.3 choice | Source |
|---|---|---|
| Health index | **3 components**: tire / engine / brake; truck HI = min | C6 `degradation_model` |
| Sensor noise | observed HI = true + `N(0, 0.03)`, clipped (POMDP) | C6 `condition_observation` |
| Frailty | per-truck per-component wear multiplier `~ Gamma(mean=1, cv)` | C6 wear heterogeneity |
| Fleet + mine | **25 trucks** in the C5 Escondida-0.1-scale mine + C6 routes A/B/C | C5.1 + C6 env |
| Decision | **dispatch only** + fixed shared **rule-based PM** | C6.1 dispatch-only |
| Heuristics | **C5.2 H0–H4 recast** as route-selection strategies | C5.2 + C6 dispatch |

## 2. Environment

- **Fleet**: 25 trucks, 350 t payload. **Temporal model (hybrid)**: a 365-day campaign; each day = 24 hour-steps. Each day carries a fixed demand quota (210 loads) spread evenly across the hours; each route has a daily capacity. Reliability, PM and CM are resolved at hour resolution (downtime in hours), matching the scale the C6 parameters were validated on.
- **Routes (the dispatch decision surface)**: three routes trade ore grade and cycle time against per-component wear. Without this surface the recast H0–H4 would dispatch identically (see §5), so it is essential, not cosmetic.

| Route | grade | cycle | tire / engine / brake wear× | daily cap |
|---|---|---|---|---|
| A short/smooth | 0.006 | 1.0 | 1.0 / 1.0 / 1.0 | 88 |
| B long/rough | 0.008 | 1.4 | 1.6 / 1.2 / 1.1 | 75 |
| C steep/heavy | 0.010 | 1.3 | 1.3 / 1.6 / 1.7 | 62 |

All parameters are carried over **verbatim** from the C6 configs (scaled ×2.5 for 10→25 trucks); none were tuned for C5.3.

## 3. Reliability Model (`mine_env/reliability_c5_3.py`)

- **Degradation**: per haul, each component loses `base_loss × route_wear× × frailty× × regime_wear× + N(0, σ)`. Base loss tire/engine/brake = 0.004/0.003/0.003.
- **Frailty**: drawn once per episode per truck per component from `Gamma(mean=1, cv)`; with `cv>0` two same-age trucks degrade at different real rates, so condition informs beyond age.
- **Sensor noise**: the rule-PM and the policies see `observed_*_hi = clip(true + N(0, 0.03))`, never the latent truth.
- **Failure hazard (Weibull-like)**: exactly 0 above `threshold_hi = 0.20`; below it, `hazard_scale × ((threshold−hi)/threshold)^shape`. A failed haul triggers **corrective maintenance (CM)**: the load is lost, an expensive long-downtime repair fires, and the component is partially restored.
- **PM vs CM restore**: both add the configured `recovery` (PM tire +0.35; CM tire +0.60) — a PM is a *partial* top-up, never a free full heal. CM costs ~4× and takes ~4× the downtime of PM, so avoiding failures is the point of PM.

---

## 4. Dispatch-Only + Rule-Based PM

- **PM is not a decision variable.** Every policy delegates maintenance to one fixed CBM engine (`pm_rule_engine_c5_3.py`): refer a component to the PM bay when its **observed** HI ≤ threshold (`tire/engine/brake = 0.21/0.21/0.28`, the C6.1 grid-search frozen optimum) or a failure-risk override fires; respect PM-bay capacity (2 bays), worst-risk first, with a per-component cooldown. This layer is byte-identical across all policies, so **only dispatch differs**.
- **Objective**: total TCO = `pm + cm + downtime + degradation + unmet_demand`. Production/cycle cost is excluded (it is identical for any policy meeting demand and created an idle-exploit in the RL Lab); C6's per-step idle term is omitted because resting under the metered daily-demand model is not waste and the production shortfall is already priced by the unmet penalty.

## 5. Heuristic Set — H0–H4 recast as route strategies

A key finding forced the route surface: in the C5.1 environment **every** H0–H4 policy dispatches identically (`first available truck → round-robin crusher`); their entire distinction lives in the PM trigger. Delegating PM to a fixed rule would therefore collapse them to one policy. Adding routes A/B/C turns each policy's *philosophy* into a route-selection rule:

| Policy | C5.2 philosophy | C5.3 route rule | C6 analogue |
|---|---|---|---|
| **H0** | calendar / baseline | route-blind round-robin | (blind baseline) |
| **H1** | due + health | route a truck's weak components to gentle routes | risk-lite |
| **H2** | PM risk priority | `value − Σ(component_risk × route_wear×)` | `risk` (risk_aware) |
| **H3** | cost-unit value | chase grade per cycle (`grade/cycle`) | `value` |
| **H4** | flow / backpressure | most-free-capacity route | `capacity` (shortest_queue) |

`H_TIME` is excluded: an operating-hours PM-timing policy has no dispatch analogue once PM is fixed. Trucks fall back to their next-preferred route when the first is at capacity (the C6 masking behaviour), so no policy strands demand.

## 6. Regimes (robustness)

Run verbatim from `c6/configs/c6_regimes.yaml`:
- **`heterogeneous_condition`** (main, = the C6.1 frailty comparison): wear ×1.2, hazard ×1.3, cm-cost ×1.2, downtime ×1.2, **frailty cv = 0.50**, noise 0.03.
- **`high_stress`**: wear ×1.5, hazard ×1.8, cm-cost ×1.3, downtime ×1.3, cv 0.30.
- **`high_demand_high_stress`**: as high_stress, **demand ×1.15** (above total route capacity → structural demand pressure).

The two stress regimes test whether the failure/CM path activates and whether the ranking flips when failure-avoidance starts to matter.

## 7. Results

Full tables in **`06_C5_3_RESULTS.md`** (`scripts/run_c5_3_dispatch_sweep.py`, 30 held-out seeds × 365 days × 3 regimes). Mean TCO (lower better):

| regime | ranking (best → worst) | best vs H0 | failure/CM regime |
|---|---|---|---|
| `heterogeneous_condition` | **H1 < H2** < H3 < H4 < H0 | −6.4% (22,397 vs 23,933) | rare (0.1 CM/run) |
| `high_stress` | **H2 < H1** < H3 < H4 < H0 | −5.1% (32,580 vs 34,315) | active (H1/H2 ~4 vs blind ~26 CM) |
| `high_demand_high_stress` | **H2 < H1** < H0 < H4 < H3 | −1.1% (48,239 vs 48,777) | active (H1/H2 ~73 vs blind ~82 CM) |

> **Headline.** With PM fixed and byte-identical across policies, **condition-aware route dispatch (H1 health, H2 risk-aware) beats every condition-blind policy (H3 value, H4 capacity, H0 baseline) on TCO in all three regimes** — H1/H2 are always the top two and beat the H0 baseline on 24–25 of 30 seeds in the mild and stress regimes (15–16/30 in the extreme regime where margins narrow). The *mechanism shifts with stress*: in the mild regime the gain comes from needing fewer PMs (failures are near-zero either way); under stress the gain comes from **avoiding failures** — condition-aware routing cuts corrective repairs ~6× under `high_stress` (≈4 vs ≈26 CM/run). And under extreme demand+stress, **chasing grade (H3) or capacity (H4) becomes worse than blind round-robin (H0)**: throughput-first dispatch backfires once reliability is the binding constraint.

H1 and H2 are statistically ~tied (their order flips between regimes within seed noise); the robust, defended signal is condition-aware ≫ condition-blind.

## 8. Honest Limitations (anti-overclaim)

1. **The failure/CM path is near-dormant in the *mild* regime, and only there.** Under `heterogeneous_condition` the frozen CBM rule (threshold 0.21, just above the 0.20 failure floor) prevents almost all failures (0–1 CM/run for every policy), so in that regime the comparison is decided by **PM frequency**, not failure avoidance — an honest null on the failure axis, of the same kind as C6.1's 0-CM CBM optimum. This is *not* hidden: the two stress regimes were run precisely to test it, and they show the failure path is real and consequential (≈70 and ≈134 CM/run for the blind policies). So the mild-regime null is a property of a well-set CBM threshold under light wear, not of the model — and the headline (condition-aware ≫ blind) holds in both the failure-free and failure-driven regimes.
2. **`avg_truck_hi` is an end-of-campaign snapshot, not a time average.** Condition-aware policies can finish with markedly lower snapshot HI because they tolerate worn trucks resting near the PM threshold (idle trucks neither degrade nor fail in this model). Read the snapshot as a state descriptor, not a health-over-time score.
3. **Scale and calibration** are C6 values scaled ×2.5; they are documented and defensible, but the absolute TCO magnitudes are specific to this calibration. The qualitative ranking is the result; the magnitudes are not a field forecast.

## 9. Reproducibility & Tests

- One NumPy RNG stream per `(policy, seed)`; identical seed → identical summary (`test_results_are_reproducible_per_seed`).
- `tests/test_c5_3_{reliability,config,policies,simulator}.py` (29 tests): 3-component aggregation, frailty CV, hazard shape, sensor-noise clipping, regime application/idempotence, dispatch-only route ranking, rule-PM eligibility/bay limits, cost-decomposition-sums-to-TCO, non-degeneracy of H0–H4, stress ≥ base.
